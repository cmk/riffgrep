# Plan 01 — Inline workflow-helper unittest into the cargo job

## Goal

Move the `Run workflow helper tests` step out of the dedicated `python`
job and into the existing `test` job, matching the template-rust /
sibling-repo CI structure. Renames `python` to `python3` while there.
The dedicated `python` job stays — it still gates the embedding /
CLAP / FAISS pytest suite, which actually needs the heavy pip-install
dance. The unittest run does not.

## Dependency Graph

```
T1 (ci.yml restructure) -> T2 (verify CI green)
```

## Tasks

### T1 — Move the unittest step

- Remove the `Run workflow helper tests` step from the `python` job
  (the step that runs `python -m unittest`).
- Add a `python3 -m unittest` step to the `test` job, between
  `cargo test` and `cargo clippy`, matching the placement used by
  `template-rust` and the other ported repos.
- Keep the `python` job's remaining structure (setup-python, pip
  install pytest+numpy+hypothesis, pytest run) intact — that's still
  load-bearing for the embedding suite.

### T2 — Verify CI

- `python -m unittest` discovery on a fresh clone runs
  `tests/test_workflow_state.py` (2 tests) — already verified
  locally.
- CI's `Check & Test` job picks up the new unittest line; its
  ubuntu runner has `python3` resolvable via PATH.
